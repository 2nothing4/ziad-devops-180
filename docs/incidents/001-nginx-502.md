# Incident 001: Nginx 502 Bad Gateway

## Symptom
Nginx returned HTTP 502 responses.

## Investigation
Checked Nginx logs → upstream connection refused.

## Root Cause
Nginx configuration referenced a Kubernetes Service name that did not exist.
`proxy_pass` pointed to `flask-service` instead of `api`.

## Resolution
Updated upstream target to correct Service name (`api`).
Redeployed Nginx configuration.

## Lesson
Kubernetes service discovery depends on exact DNS naming. Always verify Service names match deployment manifests.
